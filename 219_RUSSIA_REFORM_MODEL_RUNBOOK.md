# Руководство по запуску количественной модели реформ

**Связанный скрипт:** [tools/russia_reform_model.py](tools/russia_reform_model.py)  
**Статус:** IMPLEMENTATION / прототип арифметики сценариев, не макроэкономический прогноз.

## 1. Назначение

Скрипт на стандартной библиотеке Python формирует CSV для пяти сценариев:
- baseline — исходная конфигурация;
- fund_only — перечисления в ресурсно-экспортный фонд;
- vat_reduction — иллюстративное снижение НДС;
- targeted_discounts — иллюстративная программа скидок;
- combined — сочетание инструментов.

Скрипт считает арифметику фонда, прямые изменения налоговых поступлений в первом приближении и прямые расходы на скидки. Он **не** прогнозирует инфляцию, экономический рост, реакцию компаний, перенос НДС в цены, изменение спроса, распределительные эффекты или поведение граждан.

## 2. Проверка

Требуется Python 3.10 или новее; сторонние пакеты не нужны.

Из корня репозитория выполните:

    python tools/russia_reform_model.py --test
    python tools/russia_reform_model.py --output russia_reform_scenarios.csv

Второй запуск без файла входных данных использует только вымышленные значения для проверки работы программы. Они помечены ILLUSTRATIVE_NOT_RUSSIA_DATA и не должны использоваться в экономических выводах.

## 3. Подготовка входных данных

Создайте локальный JSON-файл, например russia_2026_inputs.json, и заполните его данными одного согласованного отчётного периода:

    {
      "year": 2026,
      "baseline_vat_rate": 0.22,
      "effective_vat_base_rub": 0,
      "state_resource_revenue_rub": 0,
      "state_export_industry_revenue_rub": 0,
      "opening_fund_assets_rub": 0,
      "fund_realized_return_rate": 0,
      "fund_payout_rub": 0,
      "discount_admin_cost_rub": 0,
      "public_budget_headroom_rub": 0,
      "metadata": {
        "status": "OFFICIAL_DATA_REVIEWED",
        "data_cutoff": "YYYY-MM-DD",
        "sources": [],
        "definitions": "Describe data definitions and reconciliation here"
      }
    }

Нулевые значения — только шаблон, а не предположение о фактических доходах или расходах. Перед запуском их необходимо заменить проверенными значениями.

Запуск с данными:

    python tools/russia_reform_model.py --input russia_2026_inputs.json --output scenarios.csv

### Определения обязательных полей

- baseline_vat_rate: ставка как доля, например 0.22 для 22%.
- effective_vat_base_rub: оценённая база для приближённого расчёта изменения поступлений; должна быть согласована с определениями НДС, вычетами, возвратами, освобождениями и импортом.
- state_resource_revenue_rub: фактически полученные государством ресурсные доходы, не валовая экспортная выручка компаний.
- state_export_industry_revenue_rub: отдельно идентифицированные государственные налоговые и дивидендные поступления, связанные с экспортом техники, оборудования и транспорта. Нельзя включать здесь всю стоимость экспорта или повторно учитывать уже включённые ресурсные платежи.
- opening_fund_assets_rub: активы фонда на начало периода.
- fund_realized_return_rate: доходность активов за период как доля; номинальная или реальная доходность должна быть явно указана в metadata. Не смешивайте номинальные доходы с реальными выплатами.
- fund_payout_rub: выплаты из фонда за период.
- discount_admin_cost_rub: административные расходы программ скидок.
- public_budget_headroom_rub: отдельно обоснованный допустимый фискальный запас для оценки прямой арифметики; это не свободные деньги по умолчанию.

## 4. Ограничения текущего прототипа

1. В сценариях доли перечислений и параметры скидок пока иллюстративны и хранятся в коде. Перед оценкой политики их необходимо вынести в конфигурацию с документированным источником и обоснованием.
2. Приближение «налоговая база × изменение ставки» не заменяет расчёт налоговых поступлений по правилам НДС. Для официального решения нужна налоговая микросимуляция или модель, согласованная с ФНС и Минфином.
3. В бюджетной дельте перечисление в фонд учитывается как отток текущего бюджета. Для консолидированного государственного сектора это одновременно перевод в актив; нельзя интерпретировать перевод как исчезновение общественного богатства.
4. Скидка в расчёте равна номинальной стоимости программы. Реальная выгода граждан ниже, если субсидия поглощается ценами, тарифами, арендой или маржой поставщика.
5. Не реализованы инфляционная модель, межотраслевая модель, реакция занятости и производства, распределение по децилям дохода, региональные различия и демографические прогнозы.
6. Не включайте персональные данные. Используйте только агрегированные официальные показатели и документируйте лицензии и условия использования наборов данных.

## 5. Критерии готовности к использованию в политике

До публичного использования численных результатов необходимы:
- проверенные официальные входные данные с датой среза и источниками;
- сверка налоговых и бюджетных величин с опубликованными итогами;
- независимый код-ревью и расширенный набор автоматических тестов;
- сценарии падения ресурсных доходов, роста инфляции и ухудшения экспорта;
- оценка влияния на домохозяйства разных доходов и регионы;
- анализ чувствительности и диапазоны неопределённости;
- отдельная публикация допущений, ограничений и результатов неудачных сценариев.

## 6. Закон развития

Модель не должна подгонять результат под заранее желаемую реформу. Она должна выявлять условия, при которых мера повышает реальную доступность необходимых благ и долгосрочную устойчивость, а также условия, при которых мера ухудшает ситуацию. Если данных недостаточно, правильный результат — «не установлено», а не выдуманная точность.

## 7. Анализ чувствительности

Добавлен отдельный сценарный инструмент: [tools/russia_reform_sensitivity.py](tools/russia_reform_sensitivity.py). Он строит 243 арифметических случая по комбинациям:
- падение ресурсных государственных доходов: 0%, 25% и 50%;
- падение государственных доходов, связанных с экспортом техники и оборудования: 0%, 25% и 50%;
- доходность фонда: −5%, 0% и значение из входных данных;
- ставка НДС: исходная, на 1 процентный пункт ниже и на 2 пункта ниже (с нижней границей 0%);
- охват программы скидок: 0,5×, 1× и 1,5× от иллюстративного количества.

Запуск:

    python tools/russia_reform_sensitivity.py --test
    python tools/russia_reform_sensitivity.py --input russia_2026_inputs.json --output sensitivity.csv

Первая команда пока не реализована как отдельный режим CLI; проверка инструмента производится через unittest:

    python -m unittest discover -s tests -v

Вторая команда должна использовать входные данные с источниками, единицами измерения и датой среза. Сетка — детерминированный стресс-тест арифметики, а не вероятностный прогноз: перечисленные шоки не являются оценкой их вероятности и не моделируют взаимосвязи между ценами, инфляцией, выпуском, спросом или налоговой базой.
